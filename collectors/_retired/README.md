# 은퇴한 수집기

`registry sync` 는 `collectors/*/meta.yaml` 만 훑는다(깊이 1). 여기 있는 수집기는
한 단계 더 들어가 있어 **등록부에서 빠지고 실행 대상이 아니다.** 코드는 남는다 —
왜 이렇게 만들었는지가 다음 수집기의 참고가 되기 때문이다.

| 수집기 | 은퇴일 | 사유 |
|---|---|---|
| `nec_election_result` | 2026-09-02 | `nec_archive` 로 대체. 같은 데이터를 훨씬 넓게 가져온다 |

## `nec_election_result` (C-002)

공공데이터포털의 개표결과 **CSV 2건**(22대 총선, 21대 대선)을 읽어 18개 레코드를
만들었다. 동작에 문제가 있어서 내린 것이 아니다 — `verified: true` 였고 격리 0이었다.

내린 이유는 **범위**다. 선관위 개표자료 아카이브 전체(대선 8회·총선 7회·지방선거 6회,
1992~2025)가 로컬에 들어오면서, 같은 `election_result` 레코드를 8배 넓은 기간으로
만들 수 있게 됐다. 두 수집기를 함께 두면 21대 대선이 서로 다른 `record_id` 로
두 번 저장돼 **L2 에서 이중 계상된다.** 그래서 하나만 남긴다.

`data/records/nec_election_result.jsonl` 도 같은 이유로 지웠다.
`data/raw/nec_election_result/` 는 절대규칙 1(raw 불변)에 따라 그대로 둔다.

**22대 총선 데이터는 현재 비어 있다.** `nec_archive` 가 대선만 다루기 때문이다.
총선은 C-005 로 아카이브에서 다시 가져온다 — 아카이브의 총선 파일은 `선거구명`
컬럼이 있고 선거구마다 후보 헤더가 반복돼 대선과 레이아웃이 다르다.

되살리려면 폴더를 `collectors/` 바로 아래로 옮기고 `registry sync` 를 다시 돌린다.
