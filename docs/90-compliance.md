# 법적 제약과 검증 규칙

> 상태: v1 구현됨 (`votelink/reference/compliance.py`) · 정책표는 `data/reference/compliance.yaml`
> 산출물이 선거법에 걸리는지 확인할 때 읽을 문서는 **이것 + 그 YAML 뿐**이다.

## 1. 이 문서가 있는 이유

`CLAUDE.md` 절대 규칙 5:

> 선거법 검증을 통과하지 않은 산출물은 웹앱에 **경고 없이** 표시하지 않는다.

이 규칙을 코드가 집행하려면 "통과했다"의 정의가 필요하다. 이 문서가 그 정의다.

## 2. 이 시스템은 적법성을 판정하지 않는다

**가장 중요한 문장이다.** 시스템이 "이 산출물은 합법이다"라고 말하는 순간, 그 판정 자체가
가장 큰 위험이 된다. 공직선거법 적용은 사실관계와 시점에 좌우되고, 우리는 둘 다 모른다.

그래서 시스템이 하는 일은 이것뿐이다:

- **검토 여부를 기록한다.**
- **검토되지 않은 것을 눈에 띄게 만든다.**

**최종 판단자는 캠프의 법률 검토다.** 시스템은 그 검토가 있었는지 없었는지만 안다.

## 3. 검토 상태 — 3상태

`Emd.code = None`("코드를 모른다"), `LeanPoint.gap_* = None`("편차를 모른다")과 **같은 정신**이다.
모르는 것을 아는 척하지 않는다.

| 상태 | 뜻 | 누가 정하나 | 웹앱의 의무 |
|---|---|---|---|
| `cleared` | **사람이 검토했다고 서명한 기록** | 캠프 법률 검토자가 정책표에 `reviewed_by`·`reviewed_at`·`note` 를 남긴다 | 조용한 배지 + 검토자·검토일 표시 |
| `unreviewed` | 아직 검토되지 않았다 (**기본값**) | 아무도 정하지 않았다는 뜻 | **콘텐츠 위에** 경고 배너 |
| `blocked` | 지금 표시하면 안 된다 | 정책표 | 내용 대신 차단 사유만 |

`cleared` 는 **시스템의 판단이 아니라 사람의 서명을 옮겨 적은 것**이다. 그래서
`reviewed_by` 가 비어 있으면 `cleared` 로 인정하지 않는다 — 서명 없는 서명란은 서명이 아니다.

## 4. Fail-closed — 이 설계의 전부

**정책표에 없는 kind는 `unreviewed` 다.** `cleared` 가 아니다.

이유: 새 분석기가 새 산출물을 내면, 아무도 코드를 고치지 않아도 자동으로 경고가 붙는다.
블랙리스트였다면 새 산출물이 조용히 무경고로 표시된다 — 규칙 5가 정확히 그 상황을 막으려는 것이다.

같은 이유로 다음도 전부 `unreviewed` 로 떨어진다:

- `status: cleared` 인데 `reviewed_by` 가 비었다
- 기간에 의존하는 판정인데 `election_day` 가 `null` 이다 (선거일을 모르면 기간을 계산할 수 없다)

**모르면 경고한다.** 모르면 통과시키지 않는다.

## 5. 위험도 구분

| 등급 | 산출물 | 왜 그 등급인가 | v0.1 |
|---|---|---|:--:|
| 저위험 | 대시보드·지도 | 선관위·행안부가 **이미 공표한 집계의 재표현**. 인용에 제약이 적다 | ✓ |
| 중위험 | 갭 리포트·타깃 우선순위 | 사실이 아니라 **해석**이다. 내부 판단용이며 외부 배포 시 재검토 | v0.2 |
| **고위험** | 메시지 자산·게시물 배치안 | **직접 선거운동 자료.** 문구·수량·위치가 전부 규제 대상 | v0.2, 기본 `blocked` |

v0.1이 저위험 화면 둘로 시작하는 것은 우연이 아니다. 검증 장치를 고위험 산출물이 생기기
**전에** 만들어 두려는 것이다. 나중에 붙이는 구조가 아니다.

## 6. v0.1에 필요한 만큼의 공직선거법

전부 적지 않는다. **지금 코드가 집행할 수 있는 것만** 적고, 나머지는 자리만 만들어 둔다.

| 항목 | v0.1에서 걸리나 | 정책표에서의 표현 |
|---|---|---|
| **사전선거운동 기간** (§59) | 대시보드·지도는 **캠프 내부 열람**이라 선거운동이 아니다. 화면을 캡처해 외부로 내보내면 달라진다 | `distribution: internal_only`. 이 값이 아닌 산출물은 기간 판정 대상이 된다 |
| **여론조사 공표 금지기간** (§108, 선거일 전 6일 ~ 투표마감) | v0.1에 `poll` 레코드가 없다. 그러나 **자리를 지금 만든다** | `blackout: poll_publication` + `election_day`. **`election_day: null` 이면 판정 불가 = `unreviewed`** |
| **AI 생성물 표시** | `voter_profile` 은 순수 수치라 해당 없음. 텍스트 트랙(`00-overview.md §4-1`)이 들어오면 즉시 해당 | `ai_generated: false` 컬럼을 지금 만든다. v0.2에 스키마를 바꾸지 않기 위해 |
| **출처 표시** | 대시보드가 공식 집계를 재가공한다. 출처를 지우면 재가공이 원본인 척하게 된다 | 정책이 아니라 **렌더 규칙**으로 강제. 카드가 `source_name` 없이는 그려지지 않는다 |

빠진 것들(현수막 수량·위치 규정, 선거공보 규격)은 **고위험 산출물이 생길 때** 이 표에 들어온다.
지금 적어두면 집행되지 않는 규칙이 문서에만 쌓인다.

## 7. 정책표는 데이터다 — `data/reference/compliance.yaml`

`districts.yaml`(획정이 바뀐다)·`party_lineage.yaml`(정치적 판단이다)과 **같은 이유**로 데이터다:

**법률 검토는 사람의 판단이고, 변호사가 파이썬을 읽지 않아도 검토·수정할 수 있어야 한다.**

```yaml
election_day: null          # 모르면 null. 기간 의존 판정은 전부 unreviewed 가 된다
default_status: unreviewed  # 정책표에 없는 kind 의 처분. cleared 로 바꾸지 않는다

outputs:
  - kind: segment_profile
    risk: low
    distribution: internal_only
    ai_generated: false
    min_confidence: 0.5
    status: cleared
    reviewed_by: ""         # 사람이 채운다. 비어 있으면 cleared 로 인정하지 않는다
    reviewed_at: ""
    note: "..."
```

`default_status` 를 `cleared` 로 바꾸는 것은 **규칙 5를 끄는 것**이다. 그렇게 하지 않는다.

## 8. 판정 — 순수 함수

`votelink/reference/compliance.py` 의 `review(record) -> Verdict(status, reasons, notes)`.

입력은 **계약 봉투 필드뿐**이다: `kind`, `confidence`, `derived_from`, `source_license`, `source_name`.

**`analyzers/registry.yaml` 이나 `AnalyzerMeta.verified` 를 읽지 않는다.** 그건 L2의 내부 상태이고,
읽는 순간 계층 무지(`00-overview.md §3`)가 깨진다. L3가 볼 수 있는 신뢰 신호는 계약 필드뿐이다.

v0.1 규칙:

| # | 조건 | 결과 |
|---|---|---|
| 1 | 정책표에 없는 kind | `unreviewed` |
| 2 | `status: cleared` 인데 `reviewed_by` 가 비었다 | `unreviewed` + 사유 |
| 3 | 기간 의존 항목인데 `election_day: null` | `unreviewed` + "선거일 미설정으로 기간 판정 불가" |
| 4 | `status: blocked` | `blocked` |
| 5 | `confidence < min_confidence` | **상태는 유지**, `notes` 에 신뢰도 경고 |
| 6 | 파생 kind인데 `derived_from` 이 비었다 | **상태는 유지**, `notes` 에 "근거 없음" |

**`notes` 는 상태와 독립적으로 항상 표시된다.** `cleared` 라도 `confidence: 0.7` 은 화면에 보인다.
검토를 통과한 것과 데이터가 튼튼한 것은 다른 문제다.

## 9. 웹앱의 표시 의무

규칙 5는 문서상의 약속이 아니라 **템플릿 구조로 집행**한다.

> 산출물 블록은 `_output.html` 매크로를 통해서만 그린다. 매크로는 `verdict` 를 **필수 인자**로 받는다.
> **경고 없이 콘텐츠만 그릴 수 있는 경로가 템플릿에 존재하지 않는다.**

- `blocked` → 콘텐츠를 렌더하지 않는다. 자리에 차단 사유만.
- `unreviewed` → 경고 배너를 **콘텐츠 위에**. 옆이나 아래가 아니다 — 읽기 전에 보여야 한다.
- `cleared` → 조용한 배지 + 검토자·검토일.
- `notes[]` → 상태와 무관하게 항상.

회귀 테스트가 이 규칙 자체다 (`tests/test_web.py`):

- 정책표에서 `segment_profile` 항목을 **지운** 상태로 대시보드를 렌더하면 9장 전부에 경고 문구가 있다
- `blocked` 로 바꾸면 payload의 수치 문자열이 HTML에 **없다**

## 10. 수집 단계의 제약

산출물이 아니라 입력 쪽 경계다. 이미 계약과 코드가 강제하고 있어 여기서는 근거만 밝힌다.

| 제약 | 어디서 강제되나 |
|---|---|
| **개인 단위 데이터 없음.** 최소 집계 단위는 행정동 | `GeoLevel` 에 개인 단위가 없다. `CLAUDE.md` 절대 규칙 3 |
| robots.txt·이용약관 준수 | `votelink/collect/http.py` 의 `polite_client` |
| 뉴스는 링크 + 메타 + 요약. 원문 전문 저장은 예외 | `NewsArticlePayload.full_text_stored` 가 `source_license == public_open` 일 때만 참을 허용 |
| 해석(감성·분류)을 수집 단계에 섞지 않음 | payload 모델의 `extra="forbid"` |

이 제약이 실제로 하나를 막고 있다: **지역 이슈 랭킹 분석기**는 뉴스 출처가 robots.txt·이용약관을
통과하지 못해 착수하지 못한 상태다 (`docs/SETUP.md` 뉴스 수집 보류 결정). 제약이 장식이 아니라는
증거로 남겨둔다.

## 11. 이 문서가 하지 않는 것

- **법률 자문이 아니다.** 조문 번호는 검토자가 찾아갈 지점을 가리킬 뿐이고, 해석하지 않는다.
- **적법성을 판정하지 않는다.** §2 참조.
- **고위험 산출물의 규칙을 미리 적지 않는다.** 집행되지 않는 규칙은 문서를 무겁게만 한다.
  메시지 자산·게시물 배치안이 실제로 생길 때 §6 표에 추가한다.
