## 무엇을
중앙선관위 개표자료 아카이브에서 **대통령선거 8회(제14~21대, 1992~2025)** 의
송파구 행정동별 개표결과를 가져온다. 후보·정당별 득표수, 선거인수, 투표수.

아카이브에는 총선 7회·지방선거 6회도 들어 있으나 **이번 범위가 아니다.**
레이아웃이 선거마다 달라 한 번에 처리하려 들면 실패한다. 대선을 먼저 관통시키고
총선은 C-005로 따로 간다.

**왜 대선을 먼저 하는가**: 전국이 동일한 선택지를 놓고 투표하므로 **동별 편차가
곧 그 동네의 진영 성향**이다. 선거구 획정 변경과 무관하고, 후보 개인기가 섞이는
총선보다 baseline으로 깨끗하다. 파일 레이아웃도 총선보다 단순하다.

## 어디서
- 출처 기관: 중앙선거관리위원회
- 위치: `data/raw/nec_archive/01_대통령선거(대선)/` (로컬. 사용자가 미리 받아 둠)
- 접근 방식: **file** — 네트워크를 타지 않는다. `fetch` 는 Excel 을 **디코딩만** 한다
- 인증 필요: 없다
- 라이선스: 공공저작물 = `public_open`

**왜 `data/raw/` 안에 원본이 있는가.** 보통 사람이 넣는 원본은 `data/incoming/`
이지만, 이 아카이브는 645MB·9,584개 파일이고 이미 불변 상태다. 이걸 다시
`data/raw/` 로 복사하는 것은 낭비다. **아카이브 자체를 이 수집기의 raw 저장소로
간주한다.** `iter_raw` 는 `*.json.gz` 만 rglob 하므로 원본 `.xls` 와 섞이지 않는다
(확인함).

## 왜 필요한가
**L2 수치 트랙의 학습 데이터가 지금은 부족해서 모델을 만들 수 없다.**

| | 현재(C-002) | 이 수집기 이후 |
|---|---|---|
| 선거 수 | 2회 | **8회** |
| 송파갑 9동 | 18행 | **72행** |
| 송파구 27동 | (미수집) | **216행** |

18행으로 회귀모델을 돌리면 과적합된 숫자에 근거를 붙이는 꼴이 된다.
이 프로젝트에서 근거 없는 전략은 실패로 간주하므로, 데이터가 이만큼 늘어나는
것이 분석기 착수의 전제다.

직접 쓰이는 곳:
- 타깃 전략 — 동별 진영 성향의 **시계열**. 한 시점이 아니라 추세를 본다
- 갭 리포트 — 인구 구성으로 설명되는 기대치 대비 편차(잔차)의 기준선
- 일정표 — 동별 시간 배분의 2차 가중치

## 공통 레코드로의 매핑
- `kind`: `election_result` · `election_type`: `presidential` — **계약 변경 없음**
- `geo_level`: `emd`
- 지역 코드: 출처에 코드가 없다. **동 이름으로 `districts.yaml` 의 `emd[].code` 조회**
  (C-002와 동일). 그래서 `mois_population` 과 `geo_code` 가 정의상 일치한다
- `observed_at`: 선거일 · `observed_precision`: `day`
- `confidence`: 1.0 (공식 확정 개표결과)
- `natural_key`: `{election_id}|{읍면동명}` — 재수집해도 같은 `record_id`
- `election_id`: `{선거일}-presidential` (예: `1992-12-18-presidential`)
- `district_name`: `서울 송파구 갑` (대선에는 선거구 개념이 없다. 분석 대상을 적는다)
- `precinct`: `null` — **투표구 행은 버리고 동 단위 행만 받는다.** 인구와 조인되는
  단위가 동이고, 투표구는 선거마다 재편돼 시계열이 되지 않는다

## 갱신 주기
- 원 데이터: 선거는 비정기. 확정 후 값이 바뀌지 않는다
- 수집 주기: **`schedule: null`** (수동/이벤트). 새 대선이 치러졌을 때만
- 증분: 개념 없음. `record_id` 가 같아 재실행해도 멱등

## 검증 결과 (2026-09-02)

`uv run votelink collect nec_archive` → **배치 8 · 파싱 72 · 유효 72 · 격리 0 (0.0%)**

- 8회 전부 산술 불변식 통과: `득표합 = 계`, `계 + 무효 = 투표수`, `투표수 ≤ 선거인수`
- `record_id` 72개 전부 유일
- **끝단 검증**: `geo_code` 집합이 `mois_population` 과 정확히 일치(교집합 9, 차집합
  양쪽 다 없음) → L2 에서 개표결과 × 인구 조인이 성립한다. 이 수집기를 만든 이유다
- 정합성: 투표율이 81.8%(1992) → 65.5%(2007) → 80.2%(2025). 2007년 저점은 실제
  헌정 최저 투표율과 맞고, 당선자 계보도 전국 결과와 일치한다
- fixture 는 전국 격자를 **송파구+강남구 실제 발췌**로 줄였다(합성 아님). 옆 구가
  들어 있어야 시군구 필터가 검증된다. 레이아웃 두 계열을 각각 남겼다:
  `sample_raw.json`(14대·구형 11KB), `sample_raw_modern.json`(21대·신형 42KB)

**부수적으로 프레임워크 결함 하나를 고쳤다.** `BaseCollector.package_dir` 가
`sys.modules` 를 실행 시점에 조회해서, 테스트가 모듈을 지우면 `KeyError` 로 죽었다.
기존 수집기 테스트는 `meta=` 를 직접 넘겨 이 경로를 타지 않아 드러나지 않았다.
클래스 생성 시점에 경로를 붙잡도록 바꿨다.

## 제약과 위험

**레이아웃이 최소 4종이다.** 코드에 박지 않고 `meta.yaml` 의 선거별
**레이아웃 프로파일**로 둔다. 새 선거를 붙이는 것이 설정 변경이어야 한다.

| 선거 | 레이아웃 특징 |
|---|---|
| 14·15대 | 4줄 헤더(정당/후보 별도 줄), `유효투표수` 컬럼, 시도·구시군 매 행 반복, `소계` 행 혼재 |
| 16대 | `위원회명=[종로구]` 섹션형, 헤더 1줄, **시도 컬럼 없음**, 투표구 행 혼재 |
| 17대 | **시도별 16개 파일로 분할** — 서울 파일만 쓴다 |
| 18~21대 | 제목행 + 2줄 헤더, 병합셀, 18대는 A열이 비어 offset 1, 20대는 헤더 1줄에 콤마 숫자 |

- **~~`무효투표수` 를 주는 파일이 없다~~ — 제안 단계의 오판이었다.** 8개 파일 전부
  `무효투표수` 열을 갖고 있다(15·16대는 `무표투표수` 로 오타가 나 있다). 계산하지
  않고 그대로 읽는다. 대신 출처가 준 `계`(후보 득표 합계) 열과 우리가 더한 값을
  **대조**한다 — 계약의 `득표합 + 무효 == 투표수` 검증만으로는 **열 인덱스가 통째로
  밀린 경우를 못 잡기 때문**이다 (`rows.check_arithmetic`)
- **후보 열 경계를 잘못 잡으면 `계` 열이 '계'라는 이름의 후보가 된다.** 득표가 두 배가
  되는데 숫자는 그럴듯하다. `AGGREGATE_LABELS` 로 집계 항목명이 후보 자리에 오면
  즉시 실패시킨다
- **`소계`·`합계` 행을 동으로 착각하면 안 된다.** 구시군 합계가 동 하나로 들어오면
  득표가 두 배가 되는데 숫자는 그럴듯해서 눈치채기 어렵다
- 데이터량: 송파갑 9동 × 8선거 = **72 레코드** (송파구 전체로 넓히면 216)
- 원본 저장: `fetch` 가 셀 그리드를 JSON 으로 담아 `data/raw/nec_archive/<날짜>/`
  에 gzip 으로 남긴다. 8개 선거 합쳐 약 20MB 예상. 이렇게 하면 **`--reparse` 가
  Excel 라이브러리 없이도 동작**한다 (디코딩은 fetch, 해석은 parse)
- **새 의존성**: `openpyxl`(.xlsx) + `xlrd`(.xls). 현재 3개뿐이라 추가가 필요하다.
  xlrd 2.x 는 `.xls` 전용이고 `.xlsx` 를 못 읽으므로 둘 다 있어야 한다
- 행정동 통폐합: 1992~2025 사이 송파구 동이 재편됐을 수 있다. **매칭 실패는
  격리로 드러난다** — 격리율이 높은 선거는 `districts.yaml` 에 과거 동명을
  별칭으로 추가할지 사람이 판단한다. 추측으로 매핑하지 않는다
- 법적 검토: 공식 개표결과 공표·인용은 자유. 출처표시만 지킨다

## 기준선 — 상위 행정단위 합계 (2026-09-03 추가)

동별 득표율은 그 자체로 의미가 없다. "무엇 대비"가 있어야 지표가 된다.
그래서 같은 파일에서 **전국 / 서울시 / 송파구** 합계 행을 함께 읽는다.
동 레코드와 `kind`·payload 가 같고 `geo_level` 만 다르므로, 분석기는 특별 취급 없이
`geo_level` 로만 분기한다.

`geo_code`: 전국은 계약상 **null**(§3), 서울시 `1100000000`, 송파구 `1171000000` —
검증된 `admmCd` 의 접두사 규칙에서 나온 값이라 새 매핑표가 필요 없다.
**전국 250개 시군구를 만들지 않은 이유가 이것이다** (절대 규칙 4를 피한다).

**33년치 총계 표기가 제각각이라 조건을 코드에 박지 않고 `meta.yaml` 규칙으로 뒀다.**
규칙 하나가 여러 행에 맞으면 합산한다.

| 회차 | 특이점 |
|---|---|
| 14·15대 | 송파구가 **'송파구'로 존재하지 않는다.** 선거구 단위(`송파구갑`·`을`·`병`)로만 나와 접두사로 잡아 합산한다 |
| 16대 | **시도 열이 없다** → 서울시를 만들 수 없다. 전국은 구 합계 244개를 더해서 만든다 |
| 17대 | 서울 파일만 읽으므로 **파일 전체가 서울시**다. 구 합계 25개 → 서울. 전국은 불가 |
| 18대 | 송파구에 `소계` 행이 **둘** (아래 참조) |
| 20·21대 | 서울 총계 표기가 `합계(특별시)` — 접두사로 잡는다 |

### `expect` 안전장치가 왜 필요했나

18대 송파구에 `소계` 행이 둘이었다. 구 전체(545,369)와 재외·부재자를 뺀
관내분(527,457). 두 행을 합치면 득표가 **정확히 두 배**가 되는데:

- `득표합 = 계` ✓ 통과 (둘 다 내부적으로 일관되므로)
- `계 + 무효 = 투표수` ✓ 통과
- 투표율 76.8% — 그럴듯하다

**기존 산술 불변식 셋을 전부 통과한다.** 오직 "몇 개 행이 잡혔는가"로만 드러난다.
그래서 규칙마다 기대 행 수를 적고, 어긋나면 실패시킨다. 14대는 2(갑·을),
15대는 3(갑·을·병), 16대 전국은 244, 17대 서울은 25처럼.

### 검증

투표율이 실제 공식 집계와 일치한다: 2002 **70.8%** · 2012 **75.8%** ·
2017 **77.2%** · 2022 **77.1%** · 2025 **79.4%**.
포함 관계(송파갑 9동 ⊂ 송파구 ⊂ 서울 ⊂ 전국)도 테스트로 건다.

## C-002 은퇴
`nec_election_result` 는 이 수집기와 **완전히 중복**된다(22대 총선·21대 대선).
이 수집기가 검증되면 은퇴시킨다. `mois_population` 은 인구 데이터라 중복이 아니며
유지한다 — 유권자 프로파일 분석에 반드시 필요하다.

은퇴 방식은 코드 삭제가 아니라 **registry 에서 내리고 문서에 사유를 남기는 것**으로
한다. 22대 총선 데이터는 C-005(총선)가 다시 가져온다.
