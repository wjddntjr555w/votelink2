# C-007: naver_news 매일 증분 cron (설계 메모)

> 상태: **제안 · 구현 보류.** 지금은 수동 실행. 이 문서는 방안과 결정 대기 항목만
> 기록한다. C-006(서울 25개 자치구 확장)의 후속이다.

## 목표

매일 새벽(06:00 KST) **새로 올라온 기사만** 받아 `data/records/naver_news.jsonl`
에 추가한다. **NAVER 검색 API 호출 수를 최소화한다.**

## 지금 메커니즘 (코드 확인)

- `collectors/naver_news/meta.yaml`: `incremental: true`, `schedule: "0 6 * * *"`
  — 선언만 있고 실행기는 없다.
- 검색 API에 기간 파라미터가 없다. 증분 = `sort=date` 로 최신순을 받다가
  **한 페이지 전체가 `since` 보다 오래되면 그 검색어를 멈춘다**
  (`collector.py` `_page_is_older_than`).
- `since` 는 `--since` 인자에서만 온다. **자동 산출·마지막 실행 시각 기록이
  코드에 없다.** `--since` 없이 돌리면 검색어당 최대 10페이지(`max_start 1000`)를
  전부 긁는다.
- `--all-districts`(C-006 동반 추가)는 `--since` 를 모든 자치구에 그대로 넘긴다
  — 이미 지원.
- 겹쳐 받아도 URL 기준 `record_id` 로 자동 중복 제거
  (`runner.py` `seen` 세트 + `docs/11-storage.md:35-39`). `data/raw/` 는 새
  날짜 디렉터리에만 쓰고 기존 파일은 건드리지 않는다.

## 방안 (권장)

```
uv run votelink collect naver_news --all-districts --since <now-2일, ISO 8601>
```

- **2일 고정 룩백 창.** 검색어당 10페이지 → 1~3페이지. 누락된 실행·늦게 색인된
  기사를 이틀 여유로 흡수. 겹치는 분은 중복 제거로 흘려보낸다.
- 호출 수 (자치구 25 × 검색어 ~7):

  | 상황 | 하루 호출 수 |
  |---|---|
  | 첫 백필 (since 없음) | ~1,700 |
  | `--since` 2일 창 | **~260** (최악 ~900) |
  | `--since` 2일 창 + 일일 검색어 4개로 축소 | ~100 |

  일 한도 25,000 대비 어느 쪽이든 여유.

## 실행기 (보류)

데이터 파이프라인이 Claude Code 실행에 의존하면 안 된다 → **Windows 작업
스케줄러 + `.ps1` 래퍼** (매일 06:00). 래퍼가: 저장소로 이동 → `--since` 날짜
계산 → `collect naver_news --all-districts --since ...` 실행 → 로그 파일 적재 →
종료코드 1이면 알림. `schedule` 스킬(클라우드 루틴)은 로컬 데이터 파이프라인
용도로 부적합.

## 정할 것 (구현 시 결정 — 미정)

1. **`since` 산출 방식**
   - (권장) 고정 2일 룩백 창. 코드 변경 없음(또는 상대표기 파싱만).
   - 저장된 `max(observed_at) - 12h` 를 `since` 로. 호출 더 절감(~150/일).
     jsonl 스캔 헬퍼 또는 CLI 플래그 필요.
   - `data/state/naver_news.json` 에 마지막 성공 실행 시각 기록 → cron 이 읽어
     `--since` 로 전달, 성공 시 갱신. 가장 정확하나 새 상태 계층·실패 처리 필요.
2. **일일 검색어 범위**
   - (권장) 매일 전체 검색어. `since` 창이 있으면 검색어당 1~3페이지라
     ~260호출/일. 랜드마크 검색어가 잡는 기사를 놓치지 않음. meta 스키마 불변.
   - 일일 핵심 3~4개(자치구명·국회의원·핵심동 2개) + 주 1회 전체 스윕.
     `meta.yaml` 에 `daily_queries` 추가 + cron 2개(일·주). ~100호출/일.
3. **`--since` 상대표기 지원**
   - (권장) `votelink/cli.py` `_parse_since` 에 `2d`/`12h` 파싱 추가(~5줄).
     cron 이 `--since 2d` 한 줄로 끝, 날짜 계산 없음. ISO 8601 기존 동작 유지.
   - 래퍼가 `(Get-Date).AddDays(-2).ToString("o")` 로 ISO 문자열 계산.
     저장소 코드 변경 0.

## 지금은 (수동)

첫 백필이 끝난 뒤부터, 필요할 때 손으로:

```
# 마지막으로 돌린 날 -1~2일을 --since 에 ISO 8601(KST) 로 준다.
uv run votelink collect naver_news --all-districts --since 2026-09-04T00:00:00+09:00
```

`--since` 를 생략하면 전량 재수집(검색어당 10페이지)이 되므로 항상 준다.
결과의 `[합계] 선거구 N/25 · 저장 M` 으로 그날 새로 들어온 건수를 확인한다.
