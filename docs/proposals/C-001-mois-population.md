# C-001: 행정안전부 주민등록 인구 (행정동 × 연령 × 성별)

## 무엇을
행정동 단위의 성별·연령대별 주민등록 인구수. 원 데이터는 통·반까지 쪼개져 있고
연령은 만0~9세부터 만100세이상까지 11개 구간으로 제공된다.
이를 행정동 × 10년 구간 × 성별로 접어서 수집한다.

## 어디서
- 출처: 행정안전부 (공공데이터포털 자동변환 오픈API)
- 데이터셋: 행정안전부_행정동별(통반단위) 성/연령별 주민등록 인구수
- URL: https://www.data.go.kr/data/15108072/openapi.do
- 접근 방식: api
- 인증: **필요.** 공공데이터포털 회원가입 → 활용신청 → 일반 인증키
- 라이선스: public_open

## 왜 필요한가
**모든 분석의 분모다.** 득표율·지지율·유동인구를 전부 인구로 나눠서 본다.

직접 쓰이는 곳:
- 타깃 전략 — 세그먼트(연령×성별×지역)의 크기를 정한다. 40대 남성이 3,000명인 동과
  300명인 동에 같은 노력을 쓸 수 없다
- 갭 리포트 — "인구 대비 득표가 낮은 계층"을 계산하려면 분모가 필요하다
- 일정표 — 어느 동에 시간을 더 쓸지의 1차 가중치

## 공통 레코드로의 매핑
- `kind`: `population`
- `geo_level`: `emd`
- 지역 코드 변환: **출처에 행정구역 코드가 없다.** 시도명·시군구명·행정동명 세 필드를
  이어붙인 전체 표기(`서울특별시 송파구 풍납1동`)로 매핑표를 조회한다.
  동명이 겹쳐도 상위 행정구역이 붙어 있어 유일하게 결정된다
- `observed_at`: 기준월의 1일, `observed_precision: month`
- `confidence`: 1.0 (표본이 아닌 전수 행정 자료)
- `natural_key`: `{기준월}|{전체 지역표기}` — 재수집해도 같은 ID가 나온다
- payload: `reference_month`, `breakdown`(9구간 × 2성별 = 18칸), `total`, `households: null`

**80세 이상 접기**: 출처의 만80~89세 / 만90~99세 / 만100세이상을 계약의 `80+` 하나로 합친다.

**세대수는 여기 없다.** 다른 데이터셋(주민등록 인구 및 세대현황)에 있으므로
필요해지면 별도 수집기로 만든다.

## 갱신 주기
- 원 데이터: 매월 말일 기준으로 익월 갱신
- 수집 주기: 매월 5일 (`0 5 5 * *`)
- 증분 수집: **불가.** 월 단위 스냅샷이므로 매번 전체를 받는다.
  `reference_month`가 달라지면 `natural_key`도 달라져 새 레코드가 된다

## 제약과 위험
- 데이터량: 전국 통·반 단위는 수십만 행. 지역구 하나만 볼 것이므로
  받은 뒤 필터링하거나, 필요하면 시군구 파라미터로 좁힌다
- rate limit: 2 req/s로 설정. 포털 일일 호출 한도가 있으므로 무한 페이징을 막는
  `max_pages` 상한을 둔다
- **엔드포인트 URL이 고정이 아니다.** 자동변환 API는 데이터셋 개정마다 uddi UUID가
  바뀐다. 그래서 코드에 박지 않고 `meta.yaml`의 `config.endpoint`에 둔다
- 형식 변경 위험: 연령 구간 필드명(`만20~29세남자`)이 바뀌면 즉시 깨진다.
  총인구수와 연령별 합을 대조해 조용히 틀리는 대신 격리되도록 했다

## 미검증 사항
이 세션에서 data.go.kr 접근이 차단되어 **실제 응답으로 검증하지 못했다.**
`meta.verified: false` 상태이며, 응답 필드명은 `aggregate.py` 상단에 모아두었다.
첫 실행 시 `--capture-fixture` → `pytest` 로 확인하고 필요하면 그 부분만 고친다.
