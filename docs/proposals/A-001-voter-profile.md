# A-001: 읍면동 유권자 프로파일 (voter_profile)

> 상태: **구현·검증 완료 (2026-09-03)**. `meta.verified: true`.
> 입력 81건(개표 72 + 인구 9) → 산출 **9건, 격리 0**. 재실행 시 교체 9·신규 0(멱등).
> 첫 L2 분석기이며 `analyzers/` 규약을 함께 정했다 → `docs/30-analysis-spec.md`.
> 접두사 `A-` = analyzer. 수집기 제안서(`C-`)와 같은 자리에 둔다.
>
> **구현 중 설계가 두 번 바뀌었다** (아래 §정당 매핑, §계산 규칙에 사유를 남겼다):
> 매핑 키가 `선거×정당` → `선거×후보`, `trend` 가 절대 기울기 → 지역구 편차 기울기.

## 무엇을

송파갑 9개 행정동 각각에 대해 **레코드 1건**을 만든다. 한 건 안에

- 진영별 득표율의 **시계열** (대선 8회, 1992~2025)
- 상위 행정단위 **대비 편차** (송파갑 / 송파구 / 서울시 / 전국)
- 연령·성별 **인구 구조**
- 요약 지표 (스윙 폭, 추세 방향)

이 들어간다. 웹앱의 "동 카드" 한 장과 1:1로 대응한다.

## 입력과 출력

| | kind | 출처 | 건수 |
|---|---|---|---|
| 입력 | `election_result` | `nec_archive` | 72 (동) + 24 (기준선, §5) |
| 입력 | `population` | `mois_population` | 9 |
| 입력 | (참조) | `districts.yaml`, `party_lineage.yaml` | — |
| **출력** | **`segment_profile`** | 이 분석기 | **9** |

**모르는 `kind` 는 무시한다** (계약 §7). 뉴스가 들어와도 이 분석기는 바뀌지 않는다.

## 왜 필요한가

최종 산출물 5종 중 **타깃 전략**과 **갭 리포트**의 직접 근거다.
"어느 동이 약한가, 그 동은 누가 사는가"에 답하지 못하면 일정표도 메시지도 짤 수 없다.

**이 분석기는 예측이 아니다.** 아래 §7의 이유로 v0.1에서 회귀모델은 만들지 않는다.
산출물 이름도 `prediction` 이 아니라 `profile` 이다.

## 계약 변경 — `segment_profile` payload 추가

`RecordKind.SEGMENT_PROFILE` 은 `enums.py` 에 이미 있으나 `payloads.py` 에 모델이 없어
현재는 Record 생성이 거부된다. **모델을 추가한다 (사용자 승인 완료, 2026-09-03).**

```python
class LeanPoint(_Payload):
    election_id: str
    election_date: str
    camp_share: dict[Camp, float]  # 진영별 득표 비율, 합 == 1.0 (±0.001)
    turnout: float  # 투표수 / 선거인수
    gap: dict[str, float] | None  # 기준선 대비 %p. 기준선 없으면 None


class SegmentProfilePayload(_Payload):
    profile_type: str  # "voter_profile"
    as_of: str  # 분석 실행 기준월 "2026-09"
    lean_series: list[LeanPoint]  # 오래된 선거 순
    swing: float  # 시계열 진폭 (§4)
    trend: Trend  # conservative_shift / stable / progressive_shift
    age_mix: dict[AgeBand, float]  # 비율. 합 == 1.0
    sex_ratio: float  # 남 / 여
    population_total: int
    population_month: str  # "2024-12"
```

`Camp` = `conservative` / `progressive` / `centrist` / `other` (§3).

**봉투 쪽:**
- `geo_level: emd`, `geo_code` = 그 동의 행정동코드 (입력과 동일)
- `observed_at` = 가장 최근 입력의 시점 (인구 기준월). 분석 실행 시각이 아니다 —
  실행할 때마다 값이 바뀌면 시계열이 망가진다
- `derived_from` = 개표 8 + 기준선 24 + 인구 1 = **33건**. 편차 계산에 쓴 기준선도
  근거이므로 전부 넣는다
- `natural_key` = `voter_profile|{geo_code}|{as_of}` → 같은 달 재실행하면 같은 `record_id`

## 정당 → 진영 매핑

1992년 민주자유당부터 2025년 국민의힘까지 회차마다 정당명이 다르다. 시계열로 비교하려면
정규화해야 하는데, **이건 정치적 판단이라 코드에 숨기지 않고 데이터로 노출한다**
(`districts.yaml` 과 같은 원칙).

`data/reference/party_lineage.yaml`:

```yaml
- election: 1992-12-18-presidential
  candidate: 김영삼
  party: 민자당           # 참고용. 키가 아니다
  camp: conservative
  source: 사용자 확정 (2026-09-03)
```

**키는 `election_id` + `candidate` 다. 정당이 아니다.**

정당을 키로 잡을 수 없는 이유가 실제 데이터에 있다. **2002년(16대) 개표자료에는
정당 열 자체가 없다** — 원본 헤더가 `위원회명·읍면동명·투표구명·선거인수·투표수·
이회창·노무현·…` 로 후보명만 준다 (파싱 결함이 아니다. `meta.yaml` 의
`party_row: null` 이 원본과 맞다). 정당을 키로 두면 8회 중 1회가 통째로 매핑 불가다.

후보명은 8회 전부 존재하고, `election_id` 와 묶으면 유일하다. 같은 사람이 회차마다
다른 위치에 있는 경우도 자연히 갈린다 — **이회창은 1997·2002년 한나라당, 2007년
무소속**이다. 정당 키였다면 이 셋이 뭉갠다.

**4분류를 쓴다 — 3분류는 2017년을 왜곡한다.** 안철수 21.4%·유승민·심상정을 전부
`other` 로 넣으면 그 해 보수 지지가 실제보다 붕괴한 것처럼 보인다. 중도표 이동은
송파갑 같은 접전지에서 가장 중요한 신호라 `centrist` 를 별도 축으로 둔다.

**매핑에 없는 정당은 격리한다.** 조용히 `other` 로 떨어뜨리면 매핑 누락과
실제 군소정당을 구분할 수 없다.

## 기준선 — nec_archive 파싱 확대 (선행 아님)

편차를 내려면 상위 단위 집계가 필요하다. **원본 raw 에 전국이 이미 들어 있다**
(2025년분 격자 22,692행 확인). 현재 파서가 `sigungu_match: "송파"` 로 걸러낼 뿐이다.

| 단위 | geo_level | geo_code | 근거 |
|---|---|---|---|
| 전국 | `nation` | (null) | 계약상 코드 금지 |
| 서울시 | `sido` | `1100000000` | 검증된 admmCd 의 접두사 규칙 |
| 송파구 | `sigungu` | `1171000000` | 〃 |

**8회 × 3 = 24레코드.** 전국 250개 시군구를 다 만들지 않으므로 시군구 코드 매핑표를
새로 구축할 필요가 없다 — 절대 규칙 4에 걸리지 않는다.

원본의 **총계 행을 읽는다.** 모든 행을 더하면 투표구 행과 동 합계 행이 섞여 이중계산된다.

**다만 전국 총계 행이 모든 파일에 있다고 가정하지 않는다.** 16대는 확인 결과
`[종로구] / 합계` 처럼 **구 단위 합계만** 보인다. 파일별로 (a) 전국 총계 행이 있으면
읽고, (b) 없으면 구 단위 합계 행만 골라 더한다. 어느 쪽이든 **동 행과 투표구 행은
절대 섞지 않는다** — 섞이면 득표가 배로 뛰는데 숫자는 그럴듯해서 눈치채기 어렵다
(C-004 가 같은 함정을 이미 겪었다). 산술 불변식으로 잡는다:
`전국 선거인수 ≈ 시도 합` 이 어긋나면 실패시킨다.

**이 작업은 분석기보다 먼저일 필요가 없다.** `gap` 은 기준선 레코드가 없으면 `None` 이고,
나중에 기준선이 들어온 뒤 **분석기를 재실행하면 코드 변경 없이 채워진다.**
3단계에서 분석기를 고쳐야 한다면 이 설계가 틀린 것이다.

예외: 17대(2007)는 시도별 16개 파일 중 서울 하나만 fetch 중이다. `meta.yaml` 의
파일 목록을 늘려야 전국 총계가 나온다.

## 계산 규칙

전부 **순수 함수**다. 네트워크 없음, LLM 없음, 난수 없음. 같은 입력 → 같은 출력.

- `camp_share` = 진영 득표 합 / (투표수 − 무효표). 분모를 선거인수로 잡지 않는다 —
  투표율 변화가 성향 변화로 오독된다
- `gap` = 이 동의 `conservative` 비율 − 기준선의 `conservative` 비율 (%p)
- `swing` = `conservative` **절대** 시계열의 최댓값 − 최솟값 (%p). 표준편차가 아니라
  진폭을 쓰는 이유: 8점짜리 표본에서 표준편차는 해석하기 어렵고, 캠프가 알고 싶은 것은
  "이 동이 얼마나 흔들리는가"의 폭이다. **여기서는 절대값이 맞다** — 스윙보터 규모는
  전국 흐름에 함께 흔들리는 것까지 포함해야 실제 크기가 나온다
- `trend` = 최근 3회 **지역구 편차**의 선형 기울기. 절대 기울기가 **아니다.**

  ```
  편차(동, 선거) = 그 동의 conservative % − 송파갑 가중평균 conservative %
  송파갑 가중평균 = Σ(9개 동 보수 득표) / Σ(9개 동 유효투표)
  ```

  **절대 기울기를 쓰면 안 되는 이유는 실측으로 확인했다.** 최근 3회가
  2017(탄핵 직후 보수 저점) → 2022 → 2025라 **9개 동이 전부 `conservative_shift`**
  로 나온다. 동별 차이를 말해야 하는 지표가 9/9 같은 값이면 정보량이 0이고,
  웹앱에 "보수 이동"이라 표시되면 오해만 부른다. 편차로 바꾸면 전국 공통 흐름이
  모든 동에서 상쇄되어 **3 / 2 / 4 로 갈린다**:

  | | 절대 기울기 | 편차 기울기 |
  |---|---|---|
  | `conservative_shift` | **9** | 3 (오륜·잠실4·잠실6) |
  | `stable` | 0 | 2 (송파2·풍납2) |
  | `progressive_shift` | 0 | 4 (풍납1·방이1·방이2·송파1) |

  기준선(전국·서울)이 **필요 없다.** 송파갑 평균은 9개 동 입력으로 직접 계산된다.
  `gap` 과 독립이므로 기준선 도입 전에도 `trend` 는 온전히 나온다

- 임계값은 코드가 아니라 `meta.yaml` 의 `config.trend_threshold` 에 둔다.
  **기본 ±0.3 %p/회** — 편차 기울기는 절대 기울기보다 스케일이 작아
  ±1.0 을 쓰면 전부 `stable` 이 된다
- `age_mix` = 연령대별 합 / 총인구
- `confidence`:

| 조건 | 값 |
|---|---|
| 8회 전부 + 기준선 4단계 + 인구 있음 | 0.9 |
| 기준선 일부 결측 | 0.7 |
| 개표 회차 결측 | 0.5 |

1.0을 주지 않는다. 실측이 아니라 파생이며, 인구가 단일 시점이기 때문이다.

## 제약과 위험

- **인구가 2024-12 한 시점뿐이다.** 과거 선거 당시의 연령 구조를 모르므로
  "고령화가 득표를 얼마나 움직였나"는 **말할 수 없다.** `age_mix` 는 현재 스냅샷이며
  시계열 해석에 쓰지 않는다. 이 분석기는 둘을 곱하지 않고 나란히 놓기만 한다
- **대선 성향으로 총선 득표를 예측할 수 없다.** 대선은 인물·전국 구도가 지배하고
  총선 지역구는 현역 프리미엄과 후보 개인기가 크다. C-005(총선)가 들어온 뒤
  둘의 상관을 **실제로 재기 전까지** 전이 가정을 세우지 않는다
- **회귀모델을 만들지 않는다.** 표본 72행에 시변 설명변수가 없다. 지금 돌리면
  계수는 데이터가 아니라 우연을 학습한다. `00-overview.md` 의 "수치 트랙 학습"은
  총선·지선 변환과 인구 시계열 확보 이후로 미룬다
- **행정동 통폐합.** 1992~2025 사이 동이 재편됐다면 시계열에 구멍이 난다.
  `nec_archive` 가 이미 8회 전부 9/9 매칭을 검증했으므로 현재는 문제없으나,
  결측 회차는 `confidence` 를 낮추고 `lean_series` 에서 빠질 뿐 **추정으로 메우지 않는다**
- 데이터량: 출력 9레코드. 무시할 수준
- 법적 검토: 공식 개표결과와 주민등록 통계의 가공·인용은 자유. 다만 산출물이
  선거운동 자료로 나갈 때는 `docs/90-compliance.md` 의 검증을 거친다

## 분석기 공통 규약 (이 제안이 함께 정하는 것)

수집기와 **의도적으로 대칭**으로 만든다. 상세는 `docs/30-analysis-spec.md` 로 뺀다.

| L1 | L2 | 왜 |
|---|---|---|
| `fetch()` 네트워크만 | `load()` 디스크만 | 부작용을 한 곳에 가둔다 |
| `parse()` 순수함수 | `compute()` 순수함수 | 재실행하면 같은 결과 |
| `map_items` 항목 격리 | 동일 | 9개 중 1개 실패가 8개를 죽이지 않게 |
| `data/rejected/` | 동일 | |
| `collectors/<id>/` 폴더 하나 | `analyzers/<id>/` | 하나 고치는 비용이 개수와 무관하게 |
| `collect <id>` | `analyze <id>` | CLI 에 자리가 이미 있다 |

**LLM 은 이 분석기에 넣지 않는다.** 넣는 순간 재실행마다 결과가 달라져 위 재현성이
깨지고, 근거 추적이 무의미해진다. 텍스트 트랙은 뉴스 수집 재개 후 별도 분석기로 단다.
