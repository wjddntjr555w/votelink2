# C-002: 중앙선관위 과거 선거 개표결과 (행정동 단위)

> 상태: **구현·검증 완료 (2026-09-01)**. `meta.verified: true`.
> 제안 당시 `access: api` 였으나 조사 결과 **file** 로 바꿨다 (아래 "어디서" 참조).

## 무엇을
송파구 갑 관할 행정동별 과거 선거 개표결과. 행정동 단위로 집계된
후보·정당별 득표수, 선거인수, 투표수, 무효투표수를 가져온다.
현재 수집 대상은 **제22대 국회의원선거(2024-04-10)** 와 **대통령선거(2025-06-03)**.
제21대 총선(2020-04-15) 등은 CSV만 추가로 넣고 `meta.yaml`의 `elections` 에
한 줄 더하면 된다 — 파서는 그대로다.

투표소(투표구) 단위는 MVP 범위 밖이다. `precinct: null`, 동 전체 집계만 받는다.

## 어디서
- 출처 기관: 중앙선거관리위원회
- URL: https://www.data.go.kr/data/15025527/fileData.do (국회의원선거 개표결과)
  / https://www.data.go.kr/data/15025528/fileData.do (대통령선거 개표결과)
- 접근 방식: **file** — 사람이 CSV를 내려받아 `data/incoming/nec_election_result/`
  에 넣으면 `fetch` 가 디코딩만 해서 읽는다
- 인증 필요: **없다.** 파일데이터는 로그인·활용신청 없이 받는다
- 라이선스: 공공저작물 제1유형(출처표시) = `public_open`

**왜 오픈API를 안 쓰는가** (2026-09-01 실제 호출로 확인):
투·개표 정보 API(15000900)의 문서화된 오퍼레이션은 `투표 결과 조회` 하나뿐이고
응답이 `totSunsu`/`totTusu`/`Turnout` 같은 **투표율 집계뿐이다** — 후보자명·정당명·
득표수·읍면동 필드가 공식 문서에 없다. `getXmntckSttusInfoInqire` 가 실재하긴 하나
미문서화이고 지역 필터가 `sdName`/`wiwName` 뿐이라 읍면동을 준다는 보장이 없다.
반면 파일데이터는 투표구 단위까지 있고 승인 대기도 없다. 수집 주기가 `null`
(선거는 비정기)이라 API 자동화의 이득도 거의 없다.

## 왜 필요한가
**수치 트랙 회귀모델의 정답(label)이다.** 과거 선거결과 × 인구통계로
읍면동별 득표율을 학습하고, 예측과 실측의 차이가 곧 산출물이 된다.

직접 쓰이는 곳:
- 타깃 전략 — 세그먼트별 "과거 득표 편차"의 기준선. 인구 대비 우리 진영
  득표가 낮았던 동·계층이 공략 대상
- 갭 리포트 — 음의 편차 구간 = 취약 지역. 이 수집기 없이는 계산 불가
- 일정표 — 동별 시간 배분의 2차 가중치(1차는 인구)

## 공통 레코드로의 매핑
- `kind`: `election_result`
- `geo_level`: `emd`
- 지역 코드 변환: **출처에 행정동코드가 없다.** 동 이름으로 `districts.yaml` 의
  `emd[].code`(행정동코드 10자리)를 조회한다. 그 값은 `mois_population` 의 실제
  응답에서 확인된 것이라 두 수집기의 `geo_code` 가 정의상 일치한다.
  `code`가 null인 동은 격리된다 — 그래서 이 수집기는 `districts.yaml` 이
  전부 채워져 있어야 동작한다 (2026-09-01 백필 완료)

  > **`법정읍면동명` 이라는 컬럼명에 속지 말 것.** 값은 실제로 **행정동**이다
  > (풍납1동/풍납2동이 따로 온다). 법정동이었다면 9개가 4개로 무너져 인구와
  > 조인이 안 됐을 것이다. 실제 파일로 확인했다.
- `observed_at`: 선거일. `observed_precision: day`
- `confidence`: 1.0 (공식 확정 개표결과, 표본 아님)
- `natural_key`: `{election_id}|{읍면동 전체표기}` — 재수집해도 같은 `record_id`
- payload(`ElectionResultPayload`):
  `election_id`, `election_type`, `district_name`, `precinct: null`,
  `eligible_voters`, `total_votes`, `results[{party, candidate, votes}]`,
  `invalid_votes`

**정당명 정규화**: 무소속·정당명 개정을 원문 그대로 보존한다(해석 금지).
비교는 L2가 파생 레코드에서 한다.

**득표 합계 규칙**: 계약 모델이 `sum(results.votes) + invalid_votes == total_votes`
를 강제한다. CSV는 이 값들을 **`후보자` 컬럼에 세로로 섞어서** 준다 —
`선거인수`/`투표수`/`무효 투표수`/`기권자수` 가 후보명과 같은 자리에 온다.
이 넷을 뺀 나머지가 실제 후보이며, 넷의 이름은 `meta.yaml` 의 `aggregate_items` 에 둔다.
동 단위로 합산하면 산식 두 개가 모두 맞는다 (실제 데이터로 18개 레코드 전부 확인).
`기권자수`는 계약 payload에 자리가 없어 버린다 — `선거인수 - 투표수` 로 복원된다.

**관외사전투표·거소투표는 행정동이 아니다.** `거소·선상투표`, `관외사전투표`,
`국외부재자투표`, `잘못 투입·구분된 투표지` 가 읍면동 컬럼에 같은 자격으로 온다.
이들은 **격리가 아니라 필터로 버린다** — 오류가 아니라 대상이 아닐 뿐이고,
격리하면 격리율이 임계(5%)를 넘어 수집 전체가 실패한다.

## 갱신 주기
- 원 데이터: 선거는 비정기. 확정 후 값이 바뀌지 않는다
- 수집 주기: **cron 없음.** `schedule: null`(수동/이벤트 실행).
  새 선거가 치러졌을 때만 돌린다
- 증분 수집: 개념 없음. 이미 수집한 과거 선거는 `record_id`가 같아 재실행해도 멱등

## 제약과 위험
- 데이터량: 원본 CSV는 전국 12~17만 행이지만 송파갑만 남기면 **9개 동 × 선거 수**.
  2026-09-01 기준 18개 레코드
- rate limit: 해당 없음(네트워크를 타지 않는다). 파일을 사람이 미리 받아 둔다
- **파일마다 인코딩과 컬럼명이 다르다.** 총선은 `cp949`/`선거구명`/`법정읍면동명`,
  대선은 `utf-8`/`구시군명`/`읍면동명`. 코드에 박지 않고 `meta.yaml` 의
  `encodings`·`columns` 후보군에서 고른다
- **선거구 필터는 정확 일치여야 한다.** `송파구` 부분일치를 쓰면 송파구을·병이
  딸려 들어오는데, 옆 지역구가 섞여도 숫자는 그럴듯해서 아무도 눈치채지 못한다
- 선거구 획정 변경: 2020↔2024 송파갑 관할 동이 다를 수 있으나, **행정동 단위로
  받으면 획정과 무관**하다(동별 개표수는 선거구가 바뀌어도 그대로).
  이것이 투표소 단위 대신 행정동 단위를 받는 또 하나의 이유
- 대선은 선거구 개념이 없어 `구시군명=송파구` 로 좁힌 뒤 동 이름으로 거른다.
  `district_name` 에는 분석 대상 선거구(`서울 송파구 갑`)를 적는다
- 법적 검토: 공식 개표결과 공표·인용은 자유. 출처표시만 지키면 된다

## 검증 결과 (2026-09-01)
실제 CSV 2건으로 `meta.verified: true`.

- 배치 2 · 파싱 18 · 유효 18 · **격리 0 (0.0%)**
- 9개 동 × 2개 선거 = 18 레코드. 계약의 득표 합계 검증을 전부 통과
- **끝단 검증**: `geo_code` 집합이 `mois_population` 과 정확히 일치(교집합 9,
  차집합 없음) → L2에서 선거결과 × 인구 조인이 성립한다. 이 수집기를 만든 이유
- 정합성: 선거인수 < 인구(19세 이상 제약 만족), 투표율 59.6~82.8%
- fixture는 전국 CSV(10.9MB)를 **송파구 실제 발췌**(1,150행, 92KB)로 줄였다.
  합성이 아니라 원본의 부분집합이며, 송파구 갑/을/병이 다 들어 있어
  선거구 정확일치 필터가 그대로 검증된다
